スロパチ取材 店さがし
アーキテクチャ

スロパチステーションの取材結果を毎朝クロールし、機種ごとに取材で取り上げられた回数の多い店舗を並べる静的サイト。サーバーもデータベースも使わず、生成した JSON をリポジトリにコミットして GitHub Pages から配信する。

  • 基準日 2026-09-15
  • pnpm ワークスペース crawler / web / shared
  • Node 24 ・ TypeScript ・ Vite 7 ・ React 19
  • 公開: longtail1371.github.io/slopachi-shop-finder

図 1クロールから公開までの流れ

処理はすべて GitHub Actions の Ubuntu ランナー上で行う。クローラが data/ の JSON を更新し、Vite はその data/ を公開ディレクトリとして成果物に含める。ブラウザは配信された machines.json を起動時に 1 回取得する。

図 2クローラの処理手順

crawler/src/main.ts の runCrawl が図の 1 から 6 を順に実行する。外部サイトとの通信は fetch の 1 箇所に集めてあり、テストでは fetch・日付・データディレクトリを引数で差し替える。

図 3集計による記事単位から機種単位への組み替え

aggregate.ts は、記事 → 機種 → 店舗という入れ子を、機種 → 店舗 → 記事の入れ子に組み替える。画面は組み替え後のデータをそのまま表示するので、機種を選ぶと店舗の一覧が出る。

図 4画面の構成と状態の持ち方

ブラウザからの通信は起動時の machines.json 取得の 1 回である。絞り込み・検索・並び替えは lib/rank.ts の純関数が取得済みの JSON から計算する。選択状態は URL クエリに書き戻すため、URL を共有すると同じ画面が開く。
